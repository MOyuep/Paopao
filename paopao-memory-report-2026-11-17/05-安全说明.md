## 一、本报告夹做了什么脱敏

| 类别 | 处理方式 |
|---|---|
| 访问令牌 / API 密钥 | **一律不出现**。报告中没有任何真实 token |
| QQ 号 / 群号 / 用户 ID | 全部替换为占位符：`<OWNER_QQ>` / `<BOT_QQ>` / `<GROUP_ID>` / `<USER_ID>` |
| 本机路径 / 用户名 | 全部替换为 `<PROJECT_ROOT>` / `<STATE>` / `<DESKTOP>` |
| 真实聊天记录 / 记忆正文 | **不含**。文档里的举例一律是**中性合成句**（"甲其实是乙""他做事认真"这类），与真实记忆无关 |
| 配置内容 | 不含。报告只描述字段语义，不贴配置值 |
| 联系人信息 | 不含任何第三方账号、昵称、关系描述 |

### 验证方式：不是靠"记得脱敏"，是靠三道检查

**检查一 · 反查真实密钥**

把运行环境里的真实访问令牌、API 密钥、账号、群号、本机用户名**全部读出来**，
逐字检查它们有没有出现在本夹的任何一个文件里。这比用正则猜"密钥长什么样"可靠。

> 结果：21 项真实敏感值，**0 命中**。

**检查二 · 反查真实记忆原文**

把每条真实记忆切成 6 字窗口，逐个检查是否出现在文档里 —— 能抓到"改写时不小心抄了原句"。

> 结果：**首轮查出 5 处真实原文被当作例子引用**（都集中在实测数据那一节），
> 已全部替换为合成句；二次检查为 0。

**检查二的补充 · 4 字窗口（上线前更仔细的一轮）**

6 字窗口会漏掉只有 4 个字的真实短语。公开版定版前又跑了一轮 **4 字窗口的双向比对**
（文档→记忆、记忆→文档），查出 **4 处 6 字窗口漏掉的真原文**：

| 位置 | 原真内容 | 已改为 |
|---|---|---|
| 01-报告 | 两句真劝告句 | 「别见外」「别客气」等通用句 |
| 04-实测数据 | 一对真对比短语（0.787 就是它的实测值） | 抽象为「重视X / 不重视」，数值保留 |
| 04-实测数据 | 一支真句里的「特别」用法 | 只留「特别」一词做子串演示 |
| 04-实测数据 | 一句真日常叙述 | 「没吃饭就出门了」合成句 |

> 剩下的 4–8 字命中全部是**通用词 / 术语**（张冠李戴、自动提取、长期记忆、第三人称…），
> 是讨论这个主题本身必用的词汇，不构成泄漏。

**检查四 · PDF 元数据指纹**

PDF 生成时会写入环境信息，这本身也是泄漏面。首版 PDF 的：

- `/Creator` 暴露了操作系统与浏览器版本（`Windows NT 10.0 … HeadlessChrome/157 … Edg/157`）
- `/Producer` 暴露了生成库与版本
- `/CreationDate` 暴露了精确生成时间

已用 pypdf 重写元数据，现在**只剩 `/Title`**，无 Creator / Producer / Author / 时间戳。

**检查三 · 工业级 PII 扫描**

按两套成熟方案实现：

| 依据 | 取用的规则 |
|---|---|
| **Microsoft Presidio** 的实体清单 | EMAIL_ADDRESS、IP_ADDRESS、PHONE_NUMBER、CREDIT_CARD（含 **Luhn 校验**）、UUID、MAC_ADDRESS、日期 |
| **detect-secrets**（Yelp）的熵阈值 | **base64 = 4.5、hex = 3.0**；且**熵命中必须附近出现关键词**（key/secret/token/密码/令牌）才报，否则噪声太大 |

比"自己写正则"强的地方：

1. 信用卡号做 **Luhn 校验**，不会把任意 16 位数字当卡号
2. **熵检测**能抓到没有固定格式的自建密钥（正则抓不到）
3. **私网 IP 自动排除**（`127.0.0.1`、`10.x`、`192.168.x` 不算 PII）
4. 熵命中要求**上下文关键词**，避免 UUID / 哈希 / 时间戳全报警

> 结果：**0 命中**。

**而且先做了阳性对照**（造一个含假邮箱、假手机、假卡号、假身份证、公网 IP、
高熵 token 的文件）验证扫描器确实能报 —— **6 项全检出，`127.0.0.1` 正确排除**。

> 这条很重要：**"0 命中"必须先证明扫描器没坏**，否则可能只是"测不出任何东西"。

### 三道检查互补，不能互相替代

一个反直觉的实测：把**含 166 处真实记忆的代码目录**拿去跑 PII 扫描，结果是 **0 命中**。

因为 PII 扫描器抓的是**结构化数据**（邮箱、手机、卡号、身份证），
而那个目录泄的是**中文散文**（测试用例里的真实句子）。

```
检查一（真实密钥）  → 抓"已知的凭据值"
检查二（记忆原文）  → 抓"中文散文泄漏"     ← PII 扫描抓不到这类
检查三（PII 扫描）  → 抓"结构化个人信息"   ← 反查抓不到未知格式的密钥
```

**三者跑齐，才敢说"已脱敏"。**

### 一个必须承认的翻车

第一次交付时我在本文档里写了"所有举例都是合成句"，**那是凭印象写的，不是查过的**。
实际有 5 处是真实记忆的原文（靠检查二发现），代码快照里还有 166 处（靠检查二发现）。

现在这句话是真的 —— 因为它是被三道检查验证过的。

**结论：本夹可以安全地给别人看，也可以安全地拷到别的地方。**

## 二、验证方式（可自己跑）

```bash
# 1) 扫密钥
grep -rniE "sk-[a-zA-Z0-9]{20,}|accessToken|api[_-]?key|secret|password" .

# 2) 扫 QQ 号（5 位以上连续数字）
grep -rnE "[0-9]{6,}" .

# 3) 扫本机路径
grep -rniE "[A-Z]:\\\\Users\\\\|/Users/|/home/" .
```

三条都应该**只在"说明性文字"里命中**，不应命中任何真实值。

## 三、真实系统里有哪些敏感面（交接给下一个维护者）

**这些都不在本报告夹里，但在运行环境里。**

### 3.1 配置文件

| 文件 | 含什么 | 保护方式 |
|---|---|---|
| `config.json` | **访问令牌**、白名单账号、模型路由 | 已在 `.gitignore` |
| `config.example.json` | 只有字段结构，**已脱敏**（令牌为空） | 可入库 |

**要点**：`config.json` 永远不要进仓库。发布前用 `config.example.json` 代替。

### 3.2 运行状态目录 `<STATE>/`

| 内容 | 敏感度 |
|---|---|
| 长期记忆正文 | **高**（个人偏好、经历、关系） |
| 会话 / 聊天记录 | **高**（完整对话） |
| 图片摘要 | **高**（描述用户发的图） |
| 用户分片 | **高**（按人分离的档案） |
| 备份目录 | **高**（历史快照，复制了上面的内容） |

**要点**：整个状态目录已在 `.gitignore`，且不应外发。备份同理。

### 3.3 归档目录

| 内容 | 风险 |
|---|---|
| 旧配置快照 | **含历史访问令牌**（已核实：17 个文件全部含） |

**建议**：如果令牌曾经泄露或共享过，**先轮换令牌，再删除这批旧快照**。
旧快照保留在当前架构下没有功能价值（当前配置才是生效的那份）。

### 3.4 密钥文件

运行环境里有独立的密钥文件（不在仓库内）。文件权限应限制为仅本人可读。

## 四、本次改动对安全性的影响

### 变好的部分

| 改动 | 安全收益 |
|---|---|
| 写入统一过闸门 | 所有写入路径都过同一套过滤，不会有某个入口绕过 |
| 元信息拦截（词表 + 模型双层） | 降低"系统内部记录混进长期记忆"的概率 |
| 归档可恢复而非删除 | 误删可回滚，减少数据损失风险 |
| 批量改动前自动备份 | 同上 |
| 冲突按证据强度裁决 | 弱证据（推断）不能覆盖强证据（原话），降低错误固化 |

### 需要注意的部分

| 改动 | 风险点 | 缓解 |
|---|---|---|
| 写入时会调用外部模型 | 记忆正文会发送到模型服务 | 只发单条正文、不发上下文；失败自动降级不影响写入 |
| 语义检索需要本地向量服务 | 若服务监听在非回环地址会暴露正文 | 建议只监听 `127.0.0.1` |
| 工具层可批量作废/恢复 | 一次调用可影响多条 | 有安全阀：不给 id/关键词时**什么都不选** |
| 置顶工具可批量操作 | 同上 | 同上 |

## 五、三条硬建议

1. **令牌轮换**：如果访问令牌曾经出现在任何日志、截图、聊天记录、共享文件里，**先换掉**。换之前不要删旧快照（会丢证据），换之后再删。
2. **状态目录永不外发**：里面是完整对话与个人档案。要分享效果就截图，不要拷目录。
3. **桌面/临时目录不放配置**：本报告夹刻意不含配置。以后做类似交付也保持这个习惯——**报告与凭据分开**。

## 六、本夹的文件清单（供核对）

```
README.md          索引与关键判断
01-报告.md          这一夜做了什么（含三处判断纠正）
02-架构.md          模块地图 / 写入链路 / 检索链路 / 数据模型
03-文献.md          引用文献，含"故意没取"的部分
04-实测数据.md      所有测量数字与产生方法
05-安全说明.md      本文件
code-说明.md        为什么这里没有代码
```

**没有 `code/` 目录，是刻意的。**

第一次生成时放了一份代码快照（路径和账号都替换过占位符），
但用"反查真实记忆原文"的方式检查后发现：**7 个文件共 166 处引用了真实记忆**
（测试用例直接拿真实数据当 fixture，评估脚本的查询由真实记忆改写，注释里举的是真实例子）。

代码对"读报告"价值很低，而清理 166 处的风险很高（替换后还要逐条确认测试语义仍成立，
且合成句会让"这测试证明的是真实场景"这句话变弱）。

**所以选择不放，而不是放一个半脱敏的版本。** 详见 `code-说明.md`。

代码在哪：

```
项目仓库 <PROJECT_ROOT>/src/                 权威版本
设计留存库 <ARCHIVE_ROOT>/memory-layer/code/  只读快照（同样含真实测试数据，不要外发）
```

## 七、这次脱敏的两次翻车（留着当教训）

**第一次**：我在安全说明里写"所有举例都是合成句"。
实测发现文档里有 **5 处**是真实原文，已改。

**第二次**：以为代码快照"是纯逻辑，不含个人信息"。
实测发现 **166 处**是真实原文，直接把 `code/` 移出桌面版。

**结论：脱敏必须靠检查，不能靠记得。**
两道检查（反查密钥、反查记忆原文）跑完之前，不要在任何地方写"已脱敏"。
