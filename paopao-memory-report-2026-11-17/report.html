01 · 这一夜做了什么

结构统一为：问题 → 做法 → 证据 → 结果。

所有数字都在 04-实测数据.md 里有产生方法。

零、起点：不是一个"不好用"的系统，是一个"会静默损坏数据"的系统

改造前最严重的几个故障，共同点是都不报错：

现象根因
一条真实约定从记忆里消失冲突判定用"词面重叠数 ≥ 2"，中文里太容易满足，一条无关的系统记录把它顶进了归档
记忆里出现"甲其实是乙"这类张冠李戴的事实没有区分"关于这个人的事实"和"关于系统维修的记录"，后者挤掉了前者
用户说的话被当成 AI 自己说的没有"谁说的"这个维度，全混在一条流里
中文单字搜不到分词器把连续汉字里的单字丢掉了
归档了但捞不回来只有作废入口，没有反向操作
同一个错误在聊天里报两次没有去重

改造的总目标不是加功能，是先让它不坏，再让它可调。

一、写入层：所有入口收口到一个函数

问题

写入有四个入口（自动提取、主动记、确认、纠正），每个都自己拼字段。

后果是具体的两次事故：

  1. 新增的 polarity 字段只接在自动提取一条路上，主动记的条目全空，覆盖率卡在 149/150。
  2. id 在重构时被删掉了，新写入的条目 id=undefined —— 而删除/恢复都是按 id 操作，等于这条记忆以后谁都动不了，但它还在有效状态、会出现在检索结果里。

做法

新建 memory-pipeline.js，导出唯一入口：

writeMemory(candidate, { items, enrich, now })
  → { action: ADD | UPDATE | CONFLICT | REJECT, item?, replaced?, verdict?, reason? }

阶段划分：
  stage 1  sanitize     规范化 + 基础过滤        （纯函数）
  stage 2  metaGate     词表级元信息拦截          （纯函数）
  stage 3  enrich       模型增强（类别/极性/重要性）（可注入，失败跳过）
  stage 4  derive       补齐全部字段              （唯一一处）
  stage 5  consolidate  合并 / 冲突消解

四个入口全部改成走它，并加了结构断言：

✅ bridge 不再直调 upsertMemory
✅ qq_remember 不再直调 upsertMemory

谁再绕过去直调，测试立刻红。

证据

改完后 polarity 覆盖率 151/151、id 缺失 0 条。

设计取舍

  • 模型调用隔离在可注入的 enrich 阶段：失败就跳过，绝不阻塞写入。
  • 核心判定是纯函数：不需要模型就能单元测试。

二、数据模型：双时态只做一个轴，且名字必须诚实

问题

想给记忆加"有效期"，一开始字段名叫 validFrom / validTo。

做法

核对文献后发现：valid_* 在双时态模型里专指世界时间（事实在世界里何时成立），而我能拿到的只是记录时间（我们何时相信）。

用 valid_* 的名字装记录时间的值，是命名撒谎——以后真要加世界时间时，这个名字已经被占死，只能被迫改名迁移。

所以字段叫 beliefFrom / beliefTo，并在注释里写死"这不是 valid-time"。

写入规则：

时机动作
条目创建beliefFrom = createdAt
冲突退役beliefTo = supersededAt
手动作废beliefTo = now
恢复清除 beliefTo

证据

✅ 有效条目不带 beliefTo
✅ 归档条目都带 beliefTo
✅ 区间不倒挂（0 条 to < from）

设计取舍

  • 归档不删除，带闭合区间保留，可恢复。这是文献里两条独立来源的共同做法。
  • 只给归档条目显示区间；有效条目不显示（空 = 仍有效，标出来只是噪音）。

三、矛盾判定：三次演进，每次都被数据推翻一次

v1：词面重叠（已废弃）

极性不同 && (相似度 ≥ 0.55 || 共享二元组 ≥ 2)

中文里"共享二元组 ≥ 2"太容易满足。 真实事故：一条"某时刻提醒我"的约定，被一条系统记录（相似度只有 0.035）判成矛盾顶进归档。

v2：剥掉否定词后比相似度

极性不同 && 剥掉否定词后相似度 ≥ 0.62

实测：

对照剥词后相似度结果
爱吃 / 不爱吃1.000判矛盾 ✓
会 / 不会1.000判矛盾 ✓
约定 / 修复记录0.035不判 ✓
喜欢 / 讨厌0.333漏判 ✗

反义词对识别不到。当时的取舍是"宁可漏判也不误删"。

v3：加语义判据（当前）

本机有本地向量服务（bge-small-zh-v1.5）。

第一版想法是错的：直接"相似度 ≥ 0.75 就判矛盾"。

做两组测量才发现不行：

测量一 · 真实数据分布（151 条有效记忆，两两 1 万余对）

最高 10 对: 0.797, 0.781, 0.749, 0.748, 0.744, 0.735...
p50=0.406  p90=0.522  p99=0.651

最相似的那对是同一件事的两条不同陈述（不是矛盾），相似度 0.797。

测量二 · 真实长度下的对照

案例相似度极性期望
上心 / 不上心0.856异矛盾
8分 / 不喜欢0.807异矛盾
重视 / 不重视0.787异矛盾
同人不同事0.797同非矛盾
极性异但不同事0.642异非矛盾
无关0.376同非矛盾

真矛盾下限 0.787，非矛盾上限 0.797 —— 区间重叠，没有可用阈值。

最终设计：极性闸门优先

① 极性相同  → 直接排除（不管向量多高）
② 极性不同  → 向量 ≥ 0.72 才判矛盾（0.642 与 0.787 之间取中）
③ 没有向量  → 降级为 v2 的词面判据

那对 0.797 的非矛盾被第①步拦住，根本不进相似度判定。

极性本身：词表不可靠

词表判极性实测有 40% 被判成"负极性"，两个原因：

  1. 「别X」是最常用的劝告句式（如「别见外」「别客气」这类通用劝告），那是给 AI 的建议，不是对事实的否定。
  2. 子串误匹配：「特别」「别人」「区别」都含「别」。

修法两层：

  • 词表去掉「别」（40% → 30%），翻过来的条目逐条看过，全是肯定句。
  • 结构化极性：抽取时让模型输出 polarity 字段，判定时字段优先，词表只作兜底。

回填历史数据时做了对照：词表判 45 条负，模型判 4 条，差的 41 条全是词表误判。所以回填必须用模型——用词表会把 41 条错误永久冻结进字段。

四、检索层：两条路径各自残缺，收口后才谈得上调优

问题

路径用什么缺什么
工具检索（对外）BM25 × 重要性 × 新鲜度 × 置顶没有向量
上下文注入（内部）BM25 + 向量 RRF没有重要性 / 新鲜度 / 置顶

对外检索换个说法就搜不到；内部注入又让旧事实和昨天的事实同等对待。

做法

新建 memory-retrieve.js，唯一入口 retrieve()：

RRF(BM25 排名, 向量排名) + 三因子

两条路径都改用它，并删掉桥接里的本地 RRF 副本。

调优：三因子不该做乘法

扩到 26 条 golden query 后暴露：

写法hit@1hit@3MRR词面档
纯 RRF19/2623/260.81610/10
RRF × 因子（原）17/2623/260.7778/10
RRF + 因子裁决（新）19/2623/260.81610/10

根因：乘法会把"相关度接近但因子不同"的条目顺序翻掉，本该第一的掉到第 2~3 位。

改法：

score = round(相关度, 1e-4)              ← 主键
      + 重要性 × 新鲜度 × 置顶 × 1e-5      ← 次键（必须小于主键步长）

相关度不被动摇；真正的平手才由三因子裁决。

效果：hit@1 恢复 19/26，词面档从 8/10 回到 10/10，而三因子依然生效。

融合策略对比

测了 8 种：

方法hit@1MRR
BM2517/260.736
向量16/260.782
RRF(1:1)19/260.816
RRF(1:2)18/260.810
归一化加法(0.5)19/260.812
RRF × 因子17/260.777

结论：RRF(1:1) 最优，保留。 加法并列但没有优势，不换。

分档看得很清楚：

档BM25向量RRF
词面10/108/1010/10
语义4/106/106/10
意图3/62/63/6

融合的价值在语义档：4/10 → 6/10。

八、这一夜踩的方法论坑

  1. 同一份逻辑写两份——踩了四次（分词器、矛盾判定、否定词表、embedding）。现在全部单一收口，并有结构断言。
  2. 新加字段只接一个入口——踩了两次（polarity、id）。现在字段补齐收口在 deriveFields。
  3. 用自造的用例测自己的实现——第一次测元信息拦截时，我写的测试句恰好命中了词表，以为通了；换成真实入口一写就漏。用真实入口测，不要用造好的样本测。
  4. 评估工具自己也要被怀疑——对比脚本里 Map 用了下标访问，导致 RRF 全 0 分，我据此得出了一个错误结论。
  5. 端口探测只用一个信号——会假阴性。要用进程表交叉验证。
  6. 判断"守护进程不稳定"前先排除自己——采样 3 分钟，PID 一次没变；所谓"反复死"全是我自己手动杀进程造成的。

二、写入链路

调用方（四个入口）
  │  · 自动提取（定时从对话提炼）
  │  · 工具主动记
  │  · 人工确认待确认记忆
  │  · 纠正
  ▼
writeMemory(candidate, { items, enrich })
  │
  ├─ stage 1  sanitize ──────────── 规范化正文、拒空、拒太长
  │             subject 归一（禁「老板/对方/用户」，统一为「他」）
  │
  ├─ stage 2  metaGate ──────────── 词表级元信息拦截（快、免费）
  │             判据：系统名词 AND 验证措辞
  │
  ├─ stage 3  enrich ────────────── 【可注入，失败跳过】
  │             一次模型调用同时产出：
  │               category   A=关于某人 / B=关于系统维修
  │               polarity   positive / negative
  │               importance 1~10
  │
  ├─ stage 4  derive ────────────── deriveFields()：补齐全部字段（唯一一处）
  │             speaker   candidate > 推断（insight→self，其余→owner）
  │             basis     candidate > 推断（insight→inferred，其余→stated）
  │             importance candidate > enrich > kind 兜底
  │             polarity  candidate > enrich > 不写（留给读时兜底）
  │             id        没有就生成
  │             status / createdAt / updatedAt
  │
  └─ stage 5  consolidate ───────── upsertMemory()
                 先找最相似的候选（同 kind、同 user）
                 再判是否矛盾（极性闸门 + 语义判据）
                 ├ 矛盾 → 按证据强度裁决（谁的原话更可信）
                 └ 不矛盾 → 合并（只在"新文包含旧文"时替换正文）
  ▼
返回 { action: ADD | UPDATE | CONFLICT | REJECT }
  │
  └─ 调用方决定后续（日志 / 回复用户 / 落盘）

落盘：调用方统一 saveAll()

为什么"返回动作"而不是"顺手做掉"

调用方需要知道发生了什么才能正确回复用户（"已记住" / "已更新" / "与旧条矛盾" / "不入库：原因"）。 如果写成"函数内部默默处理"，调用方只能猜。

分词（中文的关键）

每条内容切成：单汉字 + 双字词 + 拉丁词。

  • 单汉字保留为检索词：否则「茶」这类单字查询会漏（实测修复前搜「茶」0 条，修复后 12 条）。
  • 但单汉字不计入文档长度：否则中文天然字数多会把 BM25 分数压低。
  • 停用词单独一张表。

三因子

因子公式范围作用
重要性0.6 + 0.08 × min(10, imp)0.6 ~ 1.4约定 > 偏好 > 事实 > 判断
新鲜度30 天内 = 1；之后线性衰减，130 天触底0.45 ~ 1越新越优先
置顶置顶 × 1.31 ~ 1.3人工指定优先

四、数据模型

一条记忆的字段：

id           唯一句柄（删除/恢复/置顶都按它操作）
content      正文（主语统一第三人称「他」）
kind         fact / preference / promise / insight / lore / event / identity / weekly
speaker      owner（他说的） / self（我说的/我推的）
basis        stated（他原话） / inferred（我推断的）
polarity     positive / negative   ← 慢字段，未标注则读时用词表兜底
importance   1~10
status       live / invalid（手动作废） / superseded（被更强证据顶掉）
tags         标签数组
userId / scope / groupId   作用域
source       写入路径（auto-extract / qq_remember / correction / reflect / legacy）
beliefFrom   开始相信的时间
beliefTo     不再相信的时间（空 = 仍有效）
createdAt / updatedAt

审计字段（只在退役时写）
invalidReason / invalidatedBy
supersededBy / contentSupersededFrom
restoreNote / restoreAt
pinned / pinnedAt

三个作用域

shared    所有人可见
group     某个群可见
private   某个用户可见（默认）

默认 private 是刻意的——记忆里大量内容只该给当事人看。

7.  所有条目都有 id

9.  否定词表只有一个定义处

七、一次查询的完整例子

举例用中性合成场景，不是真实记忆内容。

输入：查询「那个人平时用什么工具」
  ↓
过滤：只看该用户可见的有效记忆 → 151 条
  ↓
词面：BM25 打分 → 排名（这条查询与原文无共同词，正确答案排第 4）
语义：向量余弦 → 排名（正确答案排第 1）
  ↓
RRF 融合：正确答案在语义排 1、词面排 4 → 融合后进前 3
  ↓
三因子：它是普通事实（importance 5）、较旧（freshness 0.9）→ 微调
  ↓
返回：正确答案命中

对比：纯词面会把这条查询排到第 4（miss top3），融合后进 top3。这就是向量那套的价值。

一、核心参考

[1] TOKI：双时态算子代数

Ziming Wang. *TOKI: A Bitemporal Operator Algebra for Contradiction Resolution

in LLM-Agent Persistent Memory.* arXiv:2606.06240.

The Hong Kong University of Science and Technology.

<https://arxiv.org/abs/2606.06240>

取了什么

论文概念本项目落地
双时态基底（valid-time × system-time 两个轴）只做 system-time 那一轴，字段名 beliefFrom / beliefTo
矛盾消解写双行：current winner + audit loser冲突时旧条转 superseded（进审计），新条 live，可恢复
审计行携带 provenance，任何更晚时间都能查归档条目保留 invalidReason / supersededBy，恢复时展示原因
四种策略按隔离级别分层：last-writer-wins / evidence-weighted / await-confirmation / per-rule默认 last-writer-wins；冲突时升级为 evidence-weighted（按依据强弱裁决）
矛盾的形式定义：subject 相同、predicate 相同、object 不同、valid-time 有交集无结构化三元组，用"文本相似度"近似前两者，"极性相反"近似第三者

故意没取

  1. 双时态只做了一个轴。

valid_ 表示事实在世界里何时成立，抽不出来（带时间词的条目只占约一成，且多为"最近/现在"这类模糊表述）。 硬填等于编造。所以字段直接叫 belief，**不叫 valid*——把那个名字留给将来真能抽出世界时间的时候。 命名撒谎比缺字段更贵。**

  1. 不做并发控制的算子代数。

论文核心贡献是把矛盾消解建模成写时并发控制（多写者 + 判定器 + 隔离级别排除异常）。 本系统是单进程串行写、没有并发、没有判定器——那套机器没有对应的问题可解。 只借用了它的数据模型那一半。

  1. 不做时间旅行查询。

能力上做得到（区间已在数据里），但使用场景不需要"某个时刻我们相信什么"。

[2] NeuSymMS：生产级神经符号记忆系统

NeuSymMS: A Hybrid Neuro-Symbolic Memory System for LLM Agents. arXiv:2605.17596.

<https://arxiv.org/abs/2605.17596>

取了什么

冲突触发条件：候选与已有事实共享 subject 和 relation，但 value 不同。

这直接塑造了矛盾判定的两段式结构：先判"是不是在讲同一件事"，再判"说的内容是否相反"。

否定被抽取器编码成显式关系（no_longer_has / stopped / lost），

规则把它们翻译成对肯定事实的撤回，否定式本身不入库。

这条让人意识到：极性应该在抽取时结构化标注，不能靠词面猜。 落地为 polarity 字段（模型抽取时输出），词面判断只作旧条目的降级路径。

这篇最重要的价值是一个反例

avoiding embedding-based retrieval or additional scoring models ...

zero-cost, low-latency decisions with explicit rule-based justification

论文明确说他们不用向量打分做矛盾判定，而用结构化的 subject+relation + 编辑距离（阈值 0.85）。

据此做了一次实测，确认单靠向量相似度分不开"矛盾"和"同一件事的两种说法"， 所以向量只能作为极性闸门之后的次级判据。

故意没取

  • 不做完整的三元组抽取（subject / relation / value）。对聊天陪伴场景成本过高，且会把自然语言表述拆碎。代价是矛盾判定只能用近似。

[3] Graphiti：带时间维的知识图谱

neoneye/agent-memory-atlas, content/systems/graphiti.md

<https://github.com/neoneye/agent-memory-atlas>

取了什么

矛盾时把旧边的 invalid_at 设为新边的 valid_at，expired_at 记为图学到它的时间，保留这条边。

旧事实可以带着已闭合的有效区间留在图里，而不是被删掉。

两条原则完全对应本项目的做法：归档保留 + beliefTo 闭合 + 可恢复。

独立印证的价值：Graphiti 的四字段（valid_at / invalid_at / created_at / expired_at） 和 TOKI 的双轴说的是同一件事。两篇独立来源印证，才敢确信"时间要分轴、退役不要删"。

[4] CJK 分词与 BM25

oh-my-openagent, PR #9275 —— 中日韩分词修正。

结论：每个汉字都应作为独立词项参与匹配，但不计入 BM25 的文档长度。

实测韩语 MRR 0.559 → 0.990。

取了什么

tokenizeZh(text)  单汉字保留（除停用词）+ 二元组 + 拉丁词
docLength(terms)  只计主词项，单汉字不计入
bm25Scores(...)   归一化用文档长度数组，不用 token 总数

这条修掉了一个真实故障：用户搜单字返回 0 条（旧分词器把连续汉字里的单字丢掉了）。

[5] EMNLP 2022：视角转换

He Said, She Said: Style Transfer with Perspective Shifting. EMNLP 2022.

四种操作：指代消解、句法重写、形式化、情绪归属。

取了什么

用于"第一人称事实的归属"问题：一条记忆写「我认为某专辑 8 分」， 读的人会以为是 AI 自己的观点，其实是用户说的。

核心原则：

a first-person fact is about its speaker, never a subject

（第一人称的事实属于说这句话的人，而不是句子里的主语）

落地为：所有关于用户的记忆一律改写成第三人称，主语只用「他」。

[6] @usetheo/memory：检索评分与融合的做法

@usetheo/memory（npm，预发布）README。

<https://www.npmjs.com/package/@usetheo/memory>

取了什么

评分 = recency(decay) × importance(LLM-judged 1-10 at write) × relevance(cosine)

检索用加法融合 (semantic + BM25 + entity_boost) / max_possible，

三条落地：

  1. 重要性在写入时由模型判 → 本项目 enrich 阶段一次模型调用同时产出 polarity 和 importance。
  2. 阈值来自实测 → 本项目所有阈值都附了产生方法。
  3. 融合方式要比较 → 本项目实测 8 种融合，最终保留 RRF。

故意没取 / 实测后没跟

  • 归一化加法融合：实测本地数据上 RRF(1:1) 略优（hit@1 19/26 vs 19/26，MRR 0.816 vs 0.812），没有换的理由。
  • 三因子做乘法：论文用乘法，本项目实测发现乘法会把 hit@1 从 19/26 拉到 17/26（相关度接近时顺序被因子翻掉），所以改成"平手裁决"。

<https://github.com/neoneye/agent-memory-atlas>

警告一：排序项方向颠倒会静默存活

两个系统在决定模型看到什么的函数里带了一个方向颠倒的排序项——

警告二：两个时间列不等于两个轴，除非有代码给它们写不同的值

警告三：不能失败的测试比没有测试更糟

一、为什么要护栏：静态阈值在流式监控下会失效

护栏监控是序贯的——每次查询后看一眼、跟阈值比一次。这带来一个隐蔽的统计学问题：

做法问题
滚动窗口 + Wilson 区间窗口每滑一次就偷看一眼，实际误报率远高于名义 5%，200 窗口下膨胀到 20–30%
Bonferroni要求查看次数 m 事先固定，流式下 m 无界，z→0 等于放弃
O'Brien-Fleming要预设总样本量 N，流式没有终点

它们都救不了 optional stopping（每看一眼就多一次误报机会）。

所以第七章的第一条纪律：静态阈值 → anytime-valid 自适应统计原语。

二、六个护栏（7.6.0 ~ 7.6.6）

7.6.0 · betting 置信序列（地基）

用 Waudby-Smith & Ramdas (2024) 的有界比例 betting CS 替代静态阈值：

财富过程  W_t = Π (1 + λ_t (X_i − θ))
Ville 不等式：P(任意时刻 W_t ≥ 1/α) ≤ α   ← 任意时刻偷看都有效
触发判定  triggered ⟺ W_t ≥ 1/α

关键实现点（两个踩过的坑）：

坑后果修法
固定 λ=1 在小差距时输钱（过度下注）期望 log-财富为负，永远积累不到 1/α改可预测 plug-in λ：λ=clip((μ̂−θ)/(θ(1−θ)), 0, 1)
λ 上限取 1/θ，X=0 时乘数=0log(0) = -∞ 直接破产上限取 1（对任意 θ∈(0,1) 有 1<1/θ，乘数恒正）

实测验证（可复现仿真）：

假警报控制（μ=0.5，偷看 250 次，α=0.05）→ 误报率 0.00% ≤ 5%  ✅
功效（μ=0.85 / μ=0.95，θ=0.7）→ 均在 300 块内触发           ✅

这就是第七章说 betting CS "比 Hoeffding 更紧"的真正来源——自适应 λ，不是固定 λ。

7.6.1 · 信念修订引擎（Noisy-OR + 双通道）

矛盾消解不只是"是/否"，而是多个竞争假设（alternatives）之间的信念更新。三个隐蔽故障逐一处置：

故障处置
平局陷阱（同一观测对多假设给接近高置信度，顺序迭代无差别抬升）分通道相对区分度 W_disc 判平局
相关源冒充独立证据（同源多次复述，违反 Noisy-OR 独立性）按 provenance 去相关 + Kish 有效样本量 n_eff
淘汰随机化（数组触顶后随机淘汰）淘汰后验最低者，平局用 LRU

公式（Pearl 1988 + Kish 1965）：

support 通道  p ← min(1 − (1−p)(1−Δ_support), 0.99)
defeat  通道  p ← p · (1 − Δ_defeater)
有效样本量    n_eff = (Σw)² / Σw²

7.6.2 · 语义熵网关

不确定性披露不能只靠 Prompt（轻量模型、长上下文指令遗忘会吃掉它），也不能靠词表（中文 27–40% 噪声）。

改用语义熵（Farquhar et al., Nature 2024）：采样多次 → 语义聚类 → 簇分布的信息熵。

SE = −Σ_c p(c) log p(c)   熵高 = 回答散落在多个语义 = 不确定

网关纪律：弃权优先于加前缀；兜底文本只进 content 通道、绝不进 tool_calls 参数区。

7.6.3 · time_agnostic 条件降权

身份、背景梗这类「真值不随时间衰减」的条目，不该吃新鲜度衰减；但又不能在平手时压过时间敏感条目。

  • 成对判据：仅当存在「相关度严格更高」的非 time_agnostic 条目时才降权，不误杀"唯一正确答案恰是 TA 且排第 1"
  • 单趟锁定：gate 基于降权前主键的 top-5，不迭代
  • 系数 0.775（[0.7,0.85] 中点，未标定种子，只作用 1e-5 次键）

7.6.4 · 融合退档 + 仲裁器

  • 三候选池并行（do-not-fuse 一等公民）

07 · 存量迁移与体检

这一章记一个一夜内复发 4 次的问题，以及最后落成的防复发机制。

它比任何单个功能都重要：靠人记的教训必然再犯，只有做成启动哨兵才可靠。

一、同一个坑，四次

次字段事故
1polarity只接一个写入入口，覆盖率卡 149/150
2beliefFrom/To改名后要迁移 199 条
3id重构时丢了，新条目没有 id（而删除/恢复/置顶都按 id 操作）
4importance改成按 kind 算，但 92% 存量仍是旧硬编码 5，检索评分里因子恒等于 1.0

根因：writeMemory → deriveFields 这条单一写入入口只保护新数据。存量数据不在任何写路径上、没有任何机制碰它、也不会报错——于是「修好的功能在旧数据上还是死的」。

二、为什么架构改了还复发

因为「单一入口」和「存量迁移」是两件不同的事：

单一写入入口  →  保证「以后新写的」按新规则生成
存量迁移      →  修正「已经写进去的」旧数据

前者的保证再强，也管不到后者。一夜四次，就是每次只改了前者、忘了后者。

三、落成的机制

1. 回填

importance 144 条回填，分布从 {5:142} 变成 {3:35, 4:5, 5:6, 6:45, 7:5, 8:31, 9:28}——7 种取值、不再 92% 挤在一个值上。

2. 启动哨兵（关键）

检测逻辑抽成 memory-audit.js，桥接每次启动自动跑：

[memory] 存量体检通过：182 条有效 / 55 条沉底，无异常

不靠人记得跑。有问题每次启动都会喊。

3. 三条迁移铁律

  1. 改字段生成逻辑/默认值 → 改前备份 → 改后跑体检 → 写迁移
  2. 判据：单一取值占比 >70% = 疑似未回填（polarity 天然偏斜，只查 100%）
  3. 迁移脚本只改目标字段，绝不碰 updatedAt（那是检索的新鲜度基准，改了等于抹平新鲜度信号）

四、两次自己的次生事故（已修）

事故后果教训
回填脚本顺手改了 updatedAt新鲜度信号被抹平，检索指标掉迁移只改目标字段
importance 进相关度排序实测拉低 hit@1（18→17）importance 是「谁进上下文预算」的判据，不是相关性

五、一个没解决的（记着）

检索评估数字会随记忆条数变化——151 条时 19/25，加 4 条新记忆变 18/25。跨数据状态不能直接比数字。要真正追踪回归，得冻结一份评估快照，这个还没做。

这一夜的关键判断（先看这个能省很多时间）

  1. 写入必须单一入口。 同一个字段在四个地方各写一遍，必然漏。改成 writeMemory() 一处补齐后，polarity/id 两次事故都消失了。
  2. 检索也必须单一入口。 两条检索路径各缺一半能力（一条没有向量、一条没有新鲜度），收口后才谈得上调优。
  3. 排序项要有方向断言。 文献点名过：倒排序的 bug 因为"只占分数零头 + 没有断言"能活很久。
  4. 阈值必须实测。 本次所有阈值（0.72、0.45、0.6~1.4）后面都附了产生它的方法和样本量。
  5. 评估工具本身要先被怀疑。 有一次我判断"RRF 不如加法"，实际是对比脚本自己有 bug。

生成桌面版时，我把 15 个源码文件复制了过来（路径和账号都替换成了占位符）。

随后做了一次反查：把每条真实记忆切成 6 字窗口，逐个检查是否出现在报告的文件里。

结果：

166 个片段命中，分布在 7 个文件：
  test-memory-contract.mjs   137 处   ← 测试用例直接用了真实记忆当数据
  eval-retrieval.mjs          30 处   ← 检索评估的 golden query 由真实记忆改写而来
  eval-fusion.mjs             30 处
  memory-schema.js            17 处   ← 注释里举的例子
  correction.js                9 处
  memory-merge.js              9 处
  memory-write.js              8 处

原因很自然：这些文件本来就是为真实数据写的—— 测试要跑真实语义，评估要在真实库上测，注释为了讲清楚用了真实例子。

为什么不"就地脱敏"

技术上能做：把测试里的真实句子换成合成句。但：

  1. 量大且分散——166 处、7 个文件，替换后还要逐个跑测试确认语义性质仍成立。
  2. 会失真——测试用例换成合成句后，和真实数据的分布就不再一致，"这测试证明的是真实场景"这句话就弱了。
  3. 收益低——代码对"读报告"几乎没有价值。要理解架构，02-架构.md 里的图比读源码快得多。

所以选择不放，而不是放一个半脱敏的版本。
