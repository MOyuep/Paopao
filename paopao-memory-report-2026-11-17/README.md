## 一句话

**把记忆系统从"会静默损坏数据"改造成"写入与检索各有单一收口、阈值全部有实测依据、关键不变量有断言保护"，并加了一层"运行时防御护栏"（betting 置信序列 + 信念修订 + 语义熵 + 融合仲裁）。**

- 契约测试：**354 项**（213 + 53 + 42 + 11 + 5 + 30），全绿
- 检索评估：26 条 golden query，融合方法 hit@1 **19/26**、MRR **0.816**
- 记忆总量：237 条（182 有效 / 55 归档）
- 存量字段体检：**每次启动自动跑**，无异常

## 这一夜的关键判断（先看这个能省很多时间）

1. **写入必须单一入口。** 同一个字段在四个地方各写一遍，必然漏。改成 `writeMemory()` 一处补齐后，`polarity`/`id` 两次事故都消失了。
2. **检索也必须单一入口。** 两条检索路径各缺一半能力（一条没有向量、一条没有新鲜度），收口后才谈得上调优。
3. **排序项要有方向断言。** 文献点名过：倒排序的 bug 因为"只占分数零头 + 没有断言"能活很久。
4. **阈值必须实测。** 本次所有阈值（0.72、0.45、0.6~1.4）后面都附了产生它的方法和样本量。
5. **评估工具本身要先被怀疑。** 有一次我判断"RRF 不如加法"，实际是对比脚本自己有 bug。

## 三处我判断错了、后来纠正的地方

留着是为了提醒：**结论要基于能复现的测量。**

| 我的第一判断 | 实测后的事实 | 怎么发现的 |
|---|---|---|
| 用 embedding 相似度当矛盾判据 | 向量分不开"矛盾"和"同一件事的不同说法"（0.787 vs 0.797 重叠） | 在真实数据上量了两两相似度分布 |
| RRF 融合不如归一化加法 | RRF(1:1) 实际最优，加法只并列 | 对比脚本修 bug 后重测 |
| 三因子乘上去更合理 | 乘法会拉低 hit@1（17→19 的差），改"平手裁决"才对 | 扩到 26 条 golden query 后暴露 |

## 还没做完的（诚实清单）

- 检索 golden set 只有 26 条，且没有"同一主题、不同时间"的用例，所以**测不出新鲜度加权到底有没有用**——只能测出它不伤害相关度。
- 没有世界时间（只有"我们何时相信"，没有"事实何时为真"）。
- 没有结构化 subject/predicate，矛盾判定仍靠文本近似。

详见 `01-报告.md` 末节。

## 开源版说明（GitHub）

本夹是**公开版**，在桌面内留档的基础上去掉了：

- 任何本机路径、用户名、盘符
- 任何账号/群号/会话标识（占位符代替）
- 所有真实记忆内容（全部换成中性合成例句）
- Windows 专用启动脚本（`打开报告.cmd`）

**脱敏方式不是靠"记得"，是靠三道检查**：反查真实密钥（读真实值逐字比对）、反查真实记忆原文（6 字窗口 + 中文过滤）、工业级 PII 扫描（Presidio 规则 + detect-secrets 熵阈值）。三道都跑过、都有阳性对照验证工具本身没坏。详见 `05-安全说明.md`。
