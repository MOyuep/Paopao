# 01 · 这一夜做了什么

> 结构统一为：**问题 → 做法 → 证据 → 结果**。
> 所有数字都在 `04-实测数据.md` 里有产生方法。

---

## 零、起点：不是一个"不好用"的系统，是一个"会静默损坏数据"的系统

改造前最严重的几个故障，共同点是**都不报错**：

| 现象 | 根因 |
|---|---|
| 一条真实约定从记忆里消失 | 冲突判定用"词面重叠数 ≥ 2"，中文里太容易满足，一条无关的系统记录把它顶进了归档 |
| 记忆里出现"甲其实是乙"这类张冠李戴的事实 | 没有区分"关于这个人的事实"和"关于系统维修的记录"，后者挤掉了前者 |
| 用户说的话被当成 AI 自己说的 | 没有"谁说的"这个维度，全混在一条流里 |
| 中文单字搜不到 | 分词器把连续汉字里的单字丢掉了 |
| 归档了但捞不回来 | 只有作废入口，没有反向操作 |
| 同一个错误在聊天里报两次 | 没有去重 |

**改造的总目标不是加功能，是先让它不坏，再让它可调。**

## 一、写入层：所有入口收口到一个函数

### 问题

写入有四个入口（自动提取、主动记、确认、纠正），每个都自己拼字段。

后果是具体的两次事故：

1. **新增的 `polarity` 字段只接在自动提取一条路上**，主动记的条目全空，覆盖率卡在 149/150。
2. **`id` 在重构时被删掉了**，新写入的条目 `id=undefined` —— 而删除/恢复都是按 id 操作，等于这条记忆**以后谁都动不了**，但它还在有效状态、会出现在检索结果里。

### 做法

新建 `memory-pipeline.js`，导出唯一入口：

```
writeMemory(candidate, { items, enrich, now })
  → { action: ADD | UPDATE | CONFLICT | REJECT, item?, replaced?, verdict?, reason? }

阶段划分：
  stage 1  sanitize     规范化 + 基础过滤        （纯函数）
  stage 2  metaGate     词表级元信息拦截          （纯函数）
  stage 3  enrich       模型增强（类别/极性/重要性）（可注入，失败跳过）
  stage 4  derive       补齐全部字段              （唯一一处）
  stage 5  consolidate  合并 / 冲突消解
```

四个入口全部改成走它，并加了**结构断言**：

```
✅ bridge 不再直调 upsertMemory
✅ qq_remember 不再直调 upsertMemory
```

谁再绕过去直调，测试立刻红。

### 证据

改完后 `polarity` 覆盖率 151/151、`id` 缺失 0 条。

### 设计取舍

- **模型调用隔离在可注入的 `enrich` 阶段**：失败就跳过，绝不阻塞写入。
- **核心判定是纯函数**：不需要模型就能单元测试。

## 二、数据模型：双时态只做一个轴，且名字必须诚实

### 问题

想给记忆加"有效期"，一开始字段名叫 `validFrom` / `validTo`。

### 做法

核对文献后发现：`valid_*` 在双时态模型里专指**世界时间**（事实在世界里何时成立），而我能拿到的只是**记录时间**（我们何时相信）。

用 `valid_*` 的名字装记录时间的值，是**命名撒谎**——以后真要加世界时间时，这个名字已经被占死，只能被迫改名迁移。

所以字段叫 `beliefFrom` / `beliefTo`，并在注释里写死"这不是 valid-time"。

写入规则：

| 时机 | 动作 |
|---|---|
| 条目创建 | `beliefFrom = createdAt` |
| 冲突退役 | `beliefTo = supersededAt` |
| 手动作废 | `beliefTo = now` |
| 恢复 | **清除** `beliefTo` |

### 证据

```
✅ 有效条目不带 beliefTo
✅ 归档条目都带 beliefTo
✅ 区间不倒挂（0 条 to < from）
```

### 设计取舍

- 归档**不删除**，带闭合区间保留，可恢复。这是文献里两条独立来源的共同做法。
- 只给归档条目显示区间；有效条目不显示（空 = 仍有效，标出来只是噪音）。

## 三、矛盾判定：三次演进，每次都被数据推翻一次

### v1：词面重叠（已废弃）

```
极性不同 && (相似度 ≥ 0.55 || 共享二元组 ≥ 2)
```

**中文里"共享二元组 ≥ 2"太容易满足。** 真实事故：一条"某时刻提醒我"的约定，被一条系统记录（相似度只有 0.035）判成矛盾顶进归档。

### v2：剥掉否定词后比相似度

```
极性不同 && 剥掉否定词后相似度 ≥ 0.62
```

实测：

| 对照 | 剥词后相似度 | 结果 |
|---|---|---|
| 爱吃 / 不爱吃 | 1.000 | 判矛盾 ✓ |
| 会 / 不会 | 1.000 | 判矛盾 ✓ |
| 约定 / 修复记录 | 0.035 | 不判 ✓ |
| **喜欢 / 讨厌** | **0.333** | **漏判** ✗ |

反义词对识别不到。当时的取舍是"宁可漏判也不误删"。

### v3：加语义判据（当前）

本机有本地向量服务（bge-small-zh-v1.5）。

**第一版想法是错的**：直接"相似度 ≥ 0.75 就判矛盾"。

做两组测量才发现不行：

**测量一 · 真实数据分布**（151 条有效记忆，两两 1 万余对）

```
最高 10 对: 0.797, 0.781, 0.749, 0.748, 0.744, 0.735...
p50=0.406  p90=0.522  p99=0.651
```

最相似的那对是**同一件事的两条不同陈述**（不是矛盾），相似度 0.797。

**测量二 · 真实长度下的对照**

| 案例 | 相似度 | 极性 | 期望 |
|---|---|---|---|
| 上心 / 不上心 | 0.856 | 异 | 矛盾 |
| 8分 / 不喜欢 | 0.807 | 异 | 矛盾 |
| 重视 / 不重视 | 0.787 | 异 | 矛盾 |
| **同人不同事** | **0.797** | **同** | **非矛盾** |
| 极性异但不同事 | 0.642 | 异 | 非矛盾 |
| 无关 | 0.376 | 同 | 非矛盾 |

**真矛盾下限 0.787，非矛盾上限 0.797 —— 区间重叠，没有可用阈值。**

### 最终设计：极性闸门优先

```
① 极性相同  → 直接排除（不管向量多高）
② 极性不同  → 向量 ≥ 0.72 才判矛盾（0.642 与 0.787 之间取中）
③ 没有向量  → 降级为 v2 的词面判据
```

那对 0.797 的非矛盾被第①步拦住，根本不进相似度判定。

### 极性本身：词表不可靠

词表判极性实测有 **40%** 被判成"负极性"，两个原因：

1. **「别X」是最常用的劝告句式**（如「别见外」「别客气」这类通用劝告），那是给 AI 的建议，不是对事实的否定。
2. **子串误匹配**：「特别」「别人」「区别」都含「别」。

修法两层：

- **词表去掉「别」**（40% → 30%），翻过来的条目逐条看过，全是肯定句。
- **结构化极性**：抽取时让模型输出 `polarity` 字段，判定时字段优先，词表只作兜底。

回填历史数据时做了对照：**词表判 45 条负，模型判 4 条**，差的 41 条全是词表误判。所以**回填必须用模型**——用词表会把 41 条错误永久冻结进字段。

## 四、检索层：两条路径各自残缺，收口后才谈得上调优

### 问题

| 路径 | 用什么 | 缺什么 |
|---|---|---|
| 工具检索（对外） | BM25 × 重要性 × 新鲜度 × 置顶 | **没有向量** |
| 上下文注入（内部） | BM25 + 向量 RRF | **没有重要性 / 新鲜度 / 置顶** |

对外检索换个说法就搜不到；内部注入又让旧事实和昨天的事实同等对待。

### 做法

新建 `memory-retrieve.js`，唯一入口 `retrieve()`：

```
RRF(BM25 排名, 向量排名) + 三因子
```

两条路径都改用它，并删掉桥接里的本地 RRF 副本。

### 调优：三因子不该做乘法

扩到 26 条 golden query 后暴露：

| 写法 | hit@1 | hit@3 | MRR | 词面档 |
|---|---|---|---|---|
| 纯 RRF | 19/26 | 23/26 | 0.816 | 10/10 |
| **RRF × 因子（原）** | **17/26** | 23/26 | 0.777 | **8/10** |
| RRF + 因子裁决（新） | **19/26** | 23/26 | 0.816 | **10/10** |

**根因**：乘法会把"相关度接近但因子不同"的条目顺序翻掉，本该第一的掉到第 2~3 位。

**改法**：

```
score = round(相关度, 1e-4)              ← 主键
      + 重要性 × 新鲜度 × 置顶 × 1e-5      ← 次键（必须小于主键步长）
```

相关度不被动摇；真正的平手才由三因子裁决。

**效果：hit@1 恢复 19/26，词面档从 8/10 回到 10/10，而三因子依然生效。**

### 融合策略对比

测了 8 种：

| 方法 | hit@1 | MRR |
|---|---|---|
| BM25 | 17/26 | 0.736 |
| 向量 | 16/26 | 0.782 |
| **RRF(1:1)** | **19/26** | **0.816** |
| RRF(1:2) | 18/26 | 0.810 |
| 归一化加法(0.5) | 19/26 | 0.812 |
| RRF × 因子 | 17/26 | 0.777 |

**结论：RRF(1:1) 最优，保留。** 加法并列但没有优势，不换。

分档看得很清楚：

| 档 | BM25 | 向量 | RRF |
|---|---|---|---|
| 词面 | **10/10** | 8/10 | **10/10** |
| 语义 | 4/10 | **6/10** | **6/10** |
| 意图 | 3/6 | 2/6 | **3/6** |

**融合的价值在语义档：4/10 → 6/10。**

## 五、稳定性：三个故障驱动的模块

### 会话历史中毒

报错 `tool_use ids were found without tool_result blocks` —— 之前只是把英文错误原样转发到聊天，而且下一轮还会失败。

现在：识别 → 换新会话 → 给一句人话 → 去重。

### 额度耗尽

中转账号 402 时之前会把错误抛给用户。现在：识别 → 设冷却（2 小时）→ 清掉会话模型映射 → 自动退回官方通道。

### 错误重复上报

同一秒两条相同错误（两个 request_id），用户看到两遍相同的抱怨。加了按 key 的去重（120 秒窗口 / 200 key）。

### 沉睡状态机

三态（清醒 / 观察中 / 沉睡）+ 观察闸门，独立成模块。

重构时做了 **500 组随机对拍**（旧实现 vs 新实现，输入相同输出必须相同），确认没改行为。

## 七、已知局限（诚实清单）

| 局限 | 影响 | 为什么暂时不修 |
|---|---|---|
| 没有结构化 subject/predicate | 矛盾判定靠文本近似，长句可能漏判 | 抽取三元组成本高，会把自然语言拆碎 |
| 只有记录时间，没有世界时间 | 回答不了"这个事实在世界里何时为真" | 抽不出来：带时间词的条目只占一成且多为模糊表述 |
| golden set 只有 26 条 | 测不出新鲜度加权是否有效 | 缺"同主题不同时间"的对照用例 |
| 词表极性仍有约三成噪声 | 历史条目极性判定不准 | 新条目已用模型标注覆盖 |
| 元信息拦截靠词表会漏 | 自然语言变体追不上 | 已加模型二次判定兜底 |

## 八、这一夜踩的方法论坑

1. **同一份逻辑写两份**——踩了四次（分词器、矛盾判定、否定词表、embedding）。现在全部单一收口，并有结构断言。
2. **新加字段只接一个入口**——踩了两次（`polarity`、`id`）。现在字段补齐收口在 `deriveFields`。
3. **用自造的用例测自己的实现**——第一次测元信息拦截时，我写的测试句恰好命中了词表，以为通了；换成真实入口一写就漏。**用真实入口测，不要用造好的样本测。**
4. **评估工具自己也要被怀疑**——对比脚本里 Map 用了下标访问，导致 RRF 全 0 分，我据此得出了一个错误结论。
5. **端口探测只用一个信号**——会假阴性。要用进程表交叉验证。
6. **判断"守护进程不稳定"前先排除自己**——采样 3 分钟，PID 一次没变；所谓"反复死"全是我自己手动杀进程造成的。
