> 这一章是**今晚后半段**的主体：从"把数据做对"推进到"让系统在运行时不静默出错"。
> 结论：六条护栏 + 三个子系统，全部落地，并以「并行信号」方式接入生产（只读观测、不改行为）。

## 一、为什么要护栏：静态阈值在流式监控下会失效

护栏监控是**序贯**的——每次查询后看一眼、跟阈值比一次。这带来一个隐蔽的统计学问题：

| 做法 | 问题 |
|---|---|
| 滚动窗口 + Wilson 区间 | 窗口每滑一次就偷看一眼，实际误报率远高于名义 5%，200 窗口下膨胀到 20–30% |
| Bonferroni | 要求查看次数 m 事先固定，流式下 m 无界，z→0 等于放弃 |
| O'Brien-Fleming | 要预设总样本量 N，流式没有终点 |

**它们都救不了 optional stopping（每看一眼就多一次误报机会）。**

所以第七章的第一条纪律：**静态阈值 → anytime-valid 自适应统计原语**。

## 二、六个护栏（7.6.0 ~ 7.6.6）

### 7.6.0 · betting 置信序列（地基）

用 Waudby-Smith & Ramdas (2024) 的有界比例 betting CS 替代静态阈值：

```
财富过程  W_t = Π (1 + λ_t (X_i − θ))
Ville 不等式：P(任意时刻 W_t ≥ 1/α) ≤ α   ← 任意时刻偷看都有效
触发判定  triggered ⟺ W_t ≥ 1/α
```

**关键实现点（两个踩过的坑）**：

| 坑 | 后果 | 修法 |
|---|---|---|
| 固定 λ=1 在小差距时输钱（过度下注） | 期望 log-财富为负，永远积累不到 1/α | 改**可预测 plug-in λ**：`λ=clip((μ̂−θ)/(θ(1−θ)), 0, 1)` |
| λ 上限取 1/θ，X=0 时乘数=0 | `log(0) = -∞` 直接破产 | 上限取 1（对任意 θ∈(0,1) 有 1<1/θ，乘数恒正） |

**实测验证**（可复现仿真）：

```
假警报控制（μ=0.5，偷看 250 次，α=0.05）→ 误报率 0.00% ≤ 5%  ✅
功效（μ=0.85 / μ=0.95，θ=0.7）→ 均在 300 块内触发           ✅
```

这就是第七章说 betting CS "比 Hoeffding 更紧"的真正来源——**自适应 λ，不是固定 λ**。

### 7.6.1 · 信念修订引擎（Noisy-OR + 双通道）

矛盾消解不只是"是/否"，而是多个竞争假设（alternatives）之间的信念更新。三个隐蔽故障逐一处置：

| 故障 | 处置 |
|---|---|
| 平局陷阱（同一观测对多假设给接近高置信度，顺序迭代无差别抬升） | 分通道相对区分度 W_disc 判平局 |
| 相关源冒充独立证据（同源多次复述，违反 Noisy-OR 独立性） | 按 provenance 去相关 + Kish 有效样本量 n_eff |
| 淘汰随机化（数组触顶后随机淘汰） | 淘汰后验最低者，平局用 LRU |

公式（Pearl 1988 + Kish 1965）：

```
support 通道  p ← min(1 − (1−p)(1−Δ_support), 0.99)
defeat  通道  p ← p · (1 − Δ_defeater)
有效样本量    n_eff = (Σw)² / Σw²
```

### 7.6.2 · 语义熵网关

不确定性披露不能只靠 Prompt（轻量模型、长上下文指令遗忘会吃掉它），也不能靠词表（中文 27–40% 噪声）。

改用**语义熵**（Farquhar et al., Nature 2024）：采样多次 → 语义聚类 → 簇分布的信息熵。

```
SE = −Σ_c p(c) log p(c)   熵高 = 回答散落在多个语义 = 不确定
```

网关纪律：弃权优先于加前缀；兜底文本只进 content 通道、**绝不进 tool_calls 参数区**。

### 7.6.3 · time_agnostic 条件降权

身份、背景梗这类「真值不随时间衰减」的条目，不该吃新鲜度衰减；但又不能在平手时压过时间敏感条目。

- **成对判据**：仅当存在「相关度严格更高」的非 time_agnostic 条目时才降权，不误杀"唯一正确答案恰是 TA 且排第 1"
- **单趟锁定**：gate 基于降权前主键的 top-5，不迭代
- 系数 0.775（[0.7,0.85] 中点，未标定种子，只作用 1e-5 次键）

### 7.6.4 · 融合退档 + 仲裁器

Fusion Tax（IEEE 2026）实证：即使最好的融合也在 13–48% 查询上把结果排到"较好的那个单路"之下。

- 三候选池并行（do-not-fuse 一等公民）
- 并集后重排（cross-encoder，可注入）
- 持续验证「仲裁器不弱于最强单路」，弱则退回最强单路

### 7.6.5 · HALO 分层监控

告警条件 = 块级 betting CS 单侧下界越过阈值，**仅此一条**——删掉「≥20」硬门槛和「连续 N 窗」（那是对同一批数据二次计入多重性）。

### 7.6.6 · 护栏元治理（SLO）

护栏自身也要被监控：长期 ~0% 触发（逻辑写死/漂到盲区）或 ~100% 触发（全局失效）都应告警。双侧用同一个 betting CS 原语。

## 四、接入生产：并行信号，不改行为

**关键决定**：六块全部以「**并行信号**」方式接入，即它们跑在真实数据上、把信号打进日志，但**不改变任何裁决/排序/回复内容**。

| 子系统 | 接在哪 | 日志关键词 |
|---|---|---|
| belief-revision | 写入路径（冲突消解） | `信念修订` |
| semantic-entropy | 注入路径（检索分散度代理） | `语义分散度诊断` |
| retrieval-arbiter | 检索路径（融合税） | `融合税诊断` |

为什么不是"直接改行为"：完整切换（信念接管裁决、LLM 采样语义熵、arbiter 退档）要么改写入逻辑（高风险）、要么加 2-3 倍 LLM 成本。正确顺序是**先攒几天真实信号，用数据决定该不该转正**。

**接入前做了备份**：`backups/pre-ch7-integration-<时间戳>/` + git tag 同名，可秒回滚。
